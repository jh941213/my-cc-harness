# Auto-Memory (작업별 선택적 메모리)

**원칙: 전부 로드하지 않는다. 이번 작업에 필요한 메모리만 읽는다.**
모든 메모리를 매번 컨텍스트에 넣는 것은 비효율이다. 항상 로드되는 것은 인덱스뿐이고, 본문은 작업 유형이 로드 조건과 일치할 때만 읽는다.

## 저장 구조

```
{project}/memory/
├── INDEX.md          # 주제 | 파일 | 로드 조건 — 세션 시작·컴팩션 후 자동 주입됨 (가볍게 유지)
├── architecture.md   # 시스템 구조, 모듈 경계, 핵심 설계 결정
├── deploy.md         # 배포 절차, CI/CD, 환경변수, 인프라 (예: 배포 작업 → docs의 cicd 문서 위치 포함)
├── testing.md        # 테스트 실행법, 픽스처, 자주 깨지는 지점
├── data-model.md     # 스키마, 마이그레이션, 데이터 흐름
├── gotchas.md        # 함정, 우회법, 환경 특이사항 (예: 회사망 TLS 프록시)
└── (필요한 주제만 추가 — 미리 만들지 않는다)
```

INDEX.md 형식:

```markdown
# Memory Index
| 주제 | 파일 | 로드 조건 (이런 작업이면 읽기) |
|------|------|------|
| 배포/CI | deploy.md | 배포, 릴리즈, CI/CD 수정, 환경변수, 인프라 작업 |
| 아키텍처 | architecture.md | 새 기능 설계, 모듈 추가, 리팩토링, 구조 질문 |
| 테스트 | testing.md | 테스트 작성/수정, 실패 디버깅 |
```

## 워크플로우

### A. 초기화 (레포에 memory/가 없을 때)
1. 레포 파악: README, docs/, CI 설정(.github/workflows 등), 매니페스트(package.json/pyproject.toml), 디렉토리 구조
2. `memory/INDEX.md` 생성 + 실제로 파악된 내용이 있는 주제 파일만 생성 (빈 스텁 금지)
3. 기존 문서(docs/ARCHITECTURE.md 등)가 있으면 내용을 복사하지 말고 **포인터로 연결** — 메모리는 문서의 요약+위치, 원본은 docs가 소유

### B. 작업 시작 시 (선택적 로드)
1. 작업 유형 분류 (배포? 기능 구현? 버그? 테스트?)
2. INDEX.md의 로드 조건과 매칭되는 파일**만** Read — 매칭 없으면 아무것도 로드하지 않는다
3. 로드한 메모리가 낡았으면(파일 경로가 없는 등) 그 자리에서 수정하거나 삭제

### C. 작업 종료 시 (기록 라우팅)
"다음에 이 유형의 작업을 할 때 알아야 하는가?"가 기준. 역할 구분:
- **`memory/{주제}.md`** — 주제별 최신 지식 (덮어쓰며 갱신, 항상 현재 상태를 반영)
- **`tasks/lessons.md`** — 시간순 작업 일지 (Stop 게이트가 강제, append-only)
- **`~/.claude/projects/*/memory/`** — 프로젝트를 넘는 사용자 선호·환경 지식만
새 주제가 생기면 파일 추가 + INDEX.md 행 추가. 한 파일이 100줄을 넘으면 분리를 검토한다.

### D. 장기 세션 (중기 메모리)
30분 이상 이어지는 작업이면 `tasks/context.md`를 유지한다:

```markdown
# 현재 작업 상태
- 목표: <검증 가능한 완료 조건>
- 핵심 결정: <결정과 이유, 한 줄씩>
- 완료: <끝난 것> / 다음: <바로 이어서 할 것>
- 주요 파일: <경로들>
```

마일스톤마다 갱신한다. 이 파일은 컴팩션 후와 세션 재시작 시 자동으로 다시 주입되므로, 여기 적힌 것은 잊혀지지 않는다.

## 금지
- 인덱스 없이 memory/ 전체를 읽는 것
- 작업과 무관한 메모리 로드
- 코드에서 파생 가능한 내용(함수 목록 등)을 메모리에 복사 — 코드가 진실의 원천
- 빈 주제 파일 미리 생성
